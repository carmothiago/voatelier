Capítulo 1Sobre este manual

Este manual foi escrito para analistas de implementação responsáveis por instalar o sistema de gestão Vitória Oliver Atelier em um servidor local, dentro da rede do ateliê. Ele assume conhecimento básico de instalação de software em Windows e navegação em pastas, mas não exige experiência prévia com PHP, MySQL ou desenvolvimento web — cada passo é detalhado e ilustrado.

💡 Como usar este manual Siga os capítulos na ordem apresentada. O Capítulo 4 (Passo a passo da instalação) é o coração deste documento — os demais capítulos complementam com contexto, verificação e solução de problemas.

O que é o sistema

O Vitória Oliver Atelier é um sistema de gestão interna para um ateliê de vestidos de noiva, cobrindo clientes, CRM, agenda, vestidos, medidas, provas, produção, estoque, fornecedores, documentos, financeiro, contratos (com geração de PDF), relatórios e auditoria. Foi construído para funcionar inteiramente offline, dentro da rede local do ateliê, sem depender de internet ou de serviços externos pagos.

Filosofia técnica do projeto

O sistema foi propositalmente construído com o mínimo de dependências possível:

  • Apenas PHP + MySQL + HTML/CSS/JavaScript — sem Node.js, Python, Docker ou Composer.
  • Arquitetura MVC simples, escrita à mão (sem frameworks como Laravel ou Symfony).
  • Compatível com qualquer instalação padrão do XAMPP no Windows.
  • Backup e geração de PDF de contratos feitos em PHP puro, sem bibliotecas externas.

Essa filosofia existe para que o sistema seja fácil de instalar, hospedar e manter por uma equipe pequena, sem depender de infraestrutura complexa.

Capítulo 2Visão geral da arquitetura

Antes de instalar, é útil entender como as peças se encaixam. A figura abaixo resume o caminho de uma requisição: o navegador (nos computadores do ateliê) fala com o Apache/PHP via HTTP; o PHP, organizado em Router → Controllers → Models → Views, consulta o MySQL via PDO e lê/grava arquivos (fotos, PDFs de contrato) na pasta uploads/.

Estrutura de pastas

O projeto segue uma estrutura de pastas previsível. Pastas com código interno ( app/, config/, database/, routes/, storage/) são bloqueadas contra acesso direto pelo navegador através de um arquivo .htaccess na raiz do projeto — só public/ (o "front controller") e uploads/ ficam acessíveis via HTTP.

📌 Por que isso importa para você, analista Ao copiar os arquivos do projeto para o servidor, copie a pasta inteira — não apenas o conteúdo de public/. O arquivo .htaccess da raiz é o que faz o roteamento funcionar corretamente mesmo acessando pela raiz do domínio.

Capítulo 4Passo a passo da instalação

Passo 1 — Instalar o XAMPP

  1. Baixe o instalador do XAMPP (com PHP 8.1+) no site oficial apachefriends.org.
  2. Execute o instalador como Administrador.
  3. Na seleção de componentes, mantenha ao menos Apache, MySQL e phpMyAdmin marcados.
  4. Finalize a instalação (local padrão recomendado: C:\xampp).
  5. Abra o XAMPP Control Panel e clique em Start ao lado de Apache e de MySQL. Os dois devem ficar com o fundo verde.
⚠️ Se a porta 80 já estiver em uso Se o Apache não iniciar porque a porta 80 está ocupada (comum quando o Skype ou o IIS estão rodando), feche o outro programa ou altere a porta do Apache em Config → Apache (httpd.conf), ajustando também o Firewall do Windows conforme a nova porta escolhida.

Passo 2 — Copiar os arquivos do sistema

  1. Extraia o arquivo .zip recebido.
  2. Copie a pasta voatelier (a pasta inteira, não apenas o conteúdo) para dentro de: 
    C:\xampp\htdocs\
  3. Confirme que o caminho final é C:\xampp\htdocs\voatelier\public\index.php — se o .zip criar uma subpasta duplicada (ex: voatelier\voatelier\), mova os arquivos um nível acima.

Passo 3 — Verificar o mod_rewrite do Apache

O sistema depende do módulo mod_rewrite do Apache para funcionar corretamente. Ele já vem ativado por padrão no XAMPP, mas vale confirmar:

  1. Abra C:\xampp\apache\conf\httpd.conf em um editor de texto (Bloco de Notas serve).
  2. Procure pela linha LoadModule rewrite_module modules/mod_rewrite.so.
  3. Confirme que ela não começa com # (o # comentaria a linha, desativando o módulo). Se estiver comentada, remova o # e salve.
  4. Se você editou o arquivo, reinicie o Apache pelo XAMPP Control Panel (Stop e depois Start).

Passo 4 — Criar o banco de dados e importar os scripts SQL

  1. Acesse http://localhost/phpmyadmin no navegador do próprio servidor.
  2. Clique em Novo no menu lateral e crie um banco chamado exatamente voatelier, com o cotejamento (collation) utf8mb4_unicode_ci.
  3. Com o banco voatelier selecionado, vá na aba Importar.
  4. Clique em Escolher arquivo, selecione o primeiro script da lista abaixo, e clique em Executar.
  5. Repita o processo para cada arquivo, sempre na ordem exata da tabela abaixo — cada script depende das tabelas criadas pelos anteriores.
#ArquivoO que faz

2database/seed.sqlCria os perfis de acesso e o usuário admin inicial

4database/seed_etapa2.sqlDados de demonstração (opcional — veja nota abaixo)

💡 Sobre os arquivos "seed" de demonstração Os arquivos seed_etapaN.sql (com N de 2 a 5) cadastram clientes, vestidos e registros fictícios para o cliente testar o sistema já com dados de exemplo. Isso é recomendado durante a fase de homologação com o ateliê. Antes de o sistema entrar em uso real, esses registros de demonstração devem ser apagados (veja o Capítulo 7).

Passo 5 — Configurar a conexão com o banco

  1. Abra o arquivo C:\xampp\htdocs\voatelier\config\database.php em um editor de texto.
  2. Na instalação padrão do XAMPP, o usuário é root e a senha é vazia — não é necessário alterar nada nesse caso.
  3. Se o MySQL desse servidor usa outro usuário/senha, ajuste os campos correspondentes no arquivo.
return [
    'driver'   => 'mysql',
    'host'     => '127.0.0.1',
    'port'     => '3306',
    'database' => 'voatelier',
    'username' => 'root',
    'password' => '',
    'charset'  => 'utf8mb4',
];

Passo 6 — Primeiro acesso

  1. No navegador, acesse http://localhost/voatelier.
  2. Você deve ver a tela de login abaixo.
  3. Entre com usuário admin e senha admin123.
  4. O sistema vai obrigar a troca dessa senha antes de liberar o acesso — defina uma senha forte e guarde em local seguro.

Capítulo 5Acesso pela rede local do ateliê

Depois de confirmar que o sistema funciona no próprio computador-servidor, libere o acesso para os outros computadores do ateliê (recepção, provador, costura etc.), todos conectados à mesma rede local.

Passo 1 — Descobrir o IP do servidor

  1. No computador-servidor, abra o Prompt de Comando (tecle Win, digite cmd, Enter).
  2. Digite ipconfig e tecle Enter.
  3. Anote o número ao lado de Endereço IPv4 (ex: 192.168.0.100).
💡 Recomendação: fixar o IP do servidor Por padrão, o roteador pode atribuir um IP diferente ao servidor depois de reiniciado. Para evitar que o endereço mude e quebre o acesso dos outros computadores, configure um IP fixo (reserva de DHCP) nas configurações do roteador, associado ao endereço MAC do computador-servidor.

Passo 2 — Liberar a porta no Firewall do Windows

  1. Abra Painel de Controle → Sistema e Segurança → Firewall do Windows Defender.
  2. Clique em Configurações Avançadas no menu lateral.
  3. Clique em Regras de Entrada → Nova Regra...
  4. Tipo de regra: Porta.
  5. Protocolo: TCP, porta específica: 80 (ou a porta configurada no Apache, se diferente).
  6. Ação: Permitir a conexão.
  7. Perfil: marque apenas Privado — desmarque Público e Domínio, para que o sistema não fique acessível fora da rede do ateliê.
  8. Dê um nome à regra (ex: "VO Atelier - Acesso Local") e finalize.

Passo 3 — Acessar dos outros computadores

Em qualquer computador conectado à mesma rede, abra o navegador e acesse http://IP_DO_SERVIDOR/voatelier, substituindo pelo IP anotado no Passo 1. Exemplo: 

http://192.168.0.100/voatelier

Capítulo 6Checklist de verificação pós-instalação

Antes de considerar a instalação concluída, confirme cada item abaixo:

Funcionalidade básica

  • A tela de login carrega em http://localhost/voatelier
  • Login com admin / admin123 funciona e força a troca de senha
  • Após trocar a senha, o Painel carrega sem erros
  • O menu lateral mostra todos os módulos (Clientes, CRM, Agenda, Vestidos, Provas, Produção, Estoque, Fornecedores, Financeiro, Contratos, Relatórios, Auditoria, Configurações)
  • Consigo abrir a ficha de um cliente de demonstração e ver suas informações

Segurança

  • Acessar http://localhost/voatelier/config/database.php retorna erro 403 (Forbidden)
  • Acessar http://localhost/voatelier/app/core/Database.php retorna erro 403
  • Um usuário sem permissão de administrador não vê os menus de Auditoria e Configurações

Rede local

  • O sistema abre normalmente a partir de pelo menos um segundo computador da rede
  • O IP do servidor foi fixado no roteador (reserva de DHCP)

Funcionalidades avançadas

  • Consigo gerar o PDF de um contrato de demonstração (menu Contratos)
  • Consigo baixar um backup do banco em Configurações → Backup
  • O Kanban do CRM e o Kanban de Produção respondem ao arrastar-e-soltar dos cards

Capítulo 7Preparando para uso em produção

Os passos anteriores deixam o sistema pronto para homologação — ou seja, para o ateliê testar com dados de exemplo. Antes de o sistema entrar em uso real no dia a dia, complete os passos abaixo.

1. Remover os dados de demonstração

Os clientes, vestidos, agendamentos e demais registros fictícios inseridos pelos arquivos seed_etapaN.sql devem ser removidos. A forma mais simples é recriar o banco do zero, executando apenas os scripts schema*.sql (estrutura) e os arquivos seed.sql / seed_etapa6.sql (que criam apenas usuários, perfis e permissões — sem dados fictícios de clientes).

⚠️ Ordem correta ao recriar o banco Apague o banco voatelier pelo phpMyAdmin e reimporte, nesta ordem: schema.sql → seed.sql → schema_etapa2.sql → schema_etapa3.sql → schema_etapa4.sql → schema_etapa5.sql → seed_etapa6.sql. Não execute os arquivos seed_etapa2.sql a seed_etapa5.sql desta vez.

2. Trocar o ambiente para produção

Abra config/config.php e altere: 

define('APP_ENV', 'production'); // era 'development'

Isso desativa a exibição de erros técnicos detalhados na tela para os usuários finais — eles passam a ver apenas mensagens amigáveis, enquanto os detalhes continuam sendo gravados em storage/logs/php-errors.log para você consultar se precisar.

3. Trocar a senha do administrador

Se você usou a senha padrão admin123 durante os testes, garanta que ela foi trocada por uma senha forte antes da entrega. O sistema já força essa troca no primeiro login, mas confirme que ninguém pulou essa etapa em um ambiente de teste anterior.

4. Cadastrar os usuários reais da equipe

Cadastre um usuário individual para cada funcionária do ateliê, com o perfil de acesso adequado (veja o Capítulo 8). Evite que a equipe compartilhe o mesmo login — isso prejudica a rastreabilidade da auditoria.

5. Configurar a rotina de backup

Defina com o cliente uma rotina periódica de backup (diária ou semanal, conforme o volume de uso). Veja o Capítulo 9 para as opções disponíveis.

Capítulo 9Backup e restauração

O sistema oferece duas formas de fazer backup:

Opção A — Pela interface (recomendada para a equipe do ateliê)

  1. Faça login com um usuário Administrador.
  2. Acesse Configurações no menu lateral.
  3. Clique em Baixar backup do banco (.sql) — o download começa na hora.
  4. Clique em Baixar uploads (.zip) para baixar as fotos e documentos anexados.
  5. Guarde os dois arquivos em um local seguro, de preferência fora do computador-servidor (pendrive, HD externo ou nuvem).

Opção B — Pela linha de comando (recomendada para automatizar)

O arquivo backup.bat, na raiz do projeto, automatiza o backup via mysqldump. Para automatizá-lo:

  1. Abra backup.bat em um editor de texto e confirme os caminhos no topo do arquivo.
  2. Teste executando o arquivo manualmente (duplo clique) e confirme que a pasta de backup foi criada.
  3. Use o Agendador de Tarefas do Windows para executar backup.bat automaticamente (ex: todos os dias às 22h).

Como restaurar um backup

  1. Abra o phpMyAdmin e crie (ou selecione) o banco voatelier.
  2. Vá em Importar e selecione o arquivo .sql do backup.
  3. Para os uploads, extraia o .zip do backup dentro da pasta uploads/ do sistema, substituindo o conteúdo atual.
💡 Teste a restauração periodicamente Um backup só tem valor se puder ser restaurado. Recomenda-se testar o processo de restauração completo (em um banco de testes separado) pelo menos uma vez, logo após a instalação, para garantir que o procedimento funciona quando for realmente necessário.
